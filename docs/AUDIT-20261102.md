# Mega Magic audit: 2026-11-02

Scope: backend (Go), frontend (React `app/` and static `web/` pages), database, workflows (CI, deploy, operations) and the live production server. Read-only: nothing was changed on the server or in the repository except this file. Method: static review, searches over the whole code base, `go vet`, `govulncheck`, `npm audit`, a throwaway PostgreSQL 17 built from `database/init.sql` plus the migrations, and read-only commands on the production server.

**Not covered:** a penetration test, a line-by-line review of every handler's authorisation logic (sampled through the route groups and a scan of every SQL statement), the Hub node service, the legacy `backend/` Python code, load testing and an automated accessibility scan. "Verified" below means I saw it on the live system or in a test; "not verified" says so.

## Size
About 54,000 lines of Go (37,500 lines of tests, 494 test files), 6,300 lines of React with 26 test files, 190 migration files, 67 tenant tables, 168 registered routes. Production: one Vultr server (2 vCPU, 4 GB), five containers, 13 MB database, 16 businesses, 16 users, 4 devices.

On Go 1.26.10 the scan reports 0 reachable vulnerabilities (2 in imported packages and 2 in required modules are not called by the code). `Dockerfile.prod` (not used for the production image) is pinned to the same version by digest.

## Priority findings

### High
1. **The `main` branch is not protected and force-pushes are allowed.** GitHub reports "Branch not protected" and no rulesets. Your notes record that `main` was force-replaced on 2026-10-25. Fix: a ruleset that blocks force-push and deletion and requires a pull request with the `validate` check. Effort: minutes.
2. **The running binary was built with Go 1.26.0, and the standard library has known vulnerabilities.** `/app/mega-magic` reports `go1.26.0`, built today at 13:32 UTC. `govulncheck` on the repo's own Go 1.26.5 finds **16 reachable standard-library vulnerabilities** (HTTP/2 server crash and memory exhaustion, TLS, x509, net/url, XML, ASN.1, and more), all fixed in 1.26.6, plus 5 in `golang.org/x/net v0.58.0`. Production runs an older release than the one measured, so it has at least these. Cause: `Dockerfile.prod` uses the floating tag `golang:1.26-alpine`, which resolved to a stale image. Fix: pin the exact version (and digest), pull on build, bump `x/net`, and run `govulncheck` in CI. Effort: small.
3. **Backups are single-copy and unproven.** Only two dumps exist, both taken by hand today, on the same server (`/var/backups/megamagic`, 1.6 MB). The nightly timer (03:10 UTC) was created today and has not yet run. No off-server copy, no restore drill, no failure alert. The Vultr disk backup (planned) would help but is not confirmed. Fix: encrypted off-site copy, a tested restore, retention and an alert. Effort: medium.
4. **Migrations are not a runnable chain, and deploys do not migrate.** On a clean database after `init.sql`, **132 of the 190 migrations fail** (Supabase-era scripts that need an `auth` schema, `anon` and `service_role` roles, an `app_role` type, `profiles` and more). The newer chain mostly applies, but at least `20261001160000_subscription_trials.sql` needs a legacy table (`service_purchases`) that a fresh database lacks. Production has **no migration bookkeeping table**, and `deploy/deploy-vps.sh` says "No schema auto-migration". So a new environment cannot be rebuilt reliably, nobody can tell which migrations production has, and code that reads a new column fails if the migration was not applied first (this is why PR #74 needs a manual step). Both Go test harnesses list migrations by hand. Fix: archive the legacy migrations, add a runner and a `schema_migrations` table, and have the deploy refuse to start code that needs a newer schema. Effort: medium.

### Medium
5. **Telegram bot tokens and webhook signing secrets are stored as plain text** (`business_telegram_bots.bot_token`, `webhook_endpoints.secret`), and therefore also in every backup. Router SSH secrets are encrypted with `secretbox`, so the helper and the key-rotation tool already exist. Fix: encrypt these two columns and migrate existing rows.
6. **The repository is public** (`RionishJovian/Vercel`) and contains the production server address, its SSH host key, the old server address and runbooks. SSH is key-only, so this is not a break-in, but it helps an attacker target you. Decide: make it private, or scrub the infrastructure details.
7. **Development seed data is in production.** `init.sql` seeds three tenants with predictable IDs. In production, "Alpha Neighborhood WISP" and "Metro Carrier Networks" exist with no users or devices. "Mega Magic Platform Admin" (`00000000-0000-0000-0000-000000000001`, `GLOBAL_ADMIN`) is the real platform-admin tenant with 2 users and 1 device. Fix: delete the two empty tenants and move seeds out of `init.sql`.
8. **Container logs are never rotated.** All five containers use the `json-file` driver with no size limit and there is no `daemon.json`. The disk is 21% used (75 GB) so there is time, but it will fill. Fix: `max-size` and `max-file`.
9. **The content security policy allows inline scripts** (`script-src 'self' 'unsafe-inline'`), needed today by the static pages and voucher print windows. This reduces the protection against injected scripts. The guest portal does escape every owner-supplied value. Fix later: move inline scripts to files.
10. **No uptime monitoring or alerting.** `/health` and `/ready` exist and return 200, but nothing watches them and nothing pages you. Fix: an external monitor on `/ready`.
11. **Dependencies and automation.** `npm audit` reports one critical advisory in `maplibre-gl` (XSS in its sanitiser). Exposure is low: the map shows only site locations with a third-party style and no user content in popups. Dependabot security updates are off, there is no CodeQL or other SAST, and no JavaScript linter is configured. Positives: secret scanning and push protection are on, and every Action is pinned by SHA.
12. **85 foreign keys have no index** on the referencing column (for example `device_change_events.device_id`, `device_config_backups.device_id`, `devices.site_id`). Harmless at 13 MB, but joins and cascading deletes slow down as data grows. A few may be covered by a differently ordered composite index; the list needs a quick review before indexing.
13. **Row-level security gaps (mitigated).** Three tenant tables have no row security (`business_invitations`, `business_memberships`, `nats_subjects`; invitations are disabled for clients). 42 of 67 tenant tables use RLS without `FORCE`, and four tables have RLS with no policy (denied to tenants by design). Mitigation, verified in production: the API connects as `mega_magic_runtime`, which is not a superuser, cannot bypass RLS and is not the table owner.

### Low
14. **Dead code that would be dangerous if reused:** `db.SetTenantContext` (builds SQL with `Sprintf` and sets a session-wide variable) has no callers, and several id-only repository mutators (`UpdateEndpoint`, `DeleteEndpoint`, `DeleteDevice`, incident `Acknowledge` and `Resolve`, portal-session deactivation) have no callers. Delete them so nobody wires them in later.
15. **Login hardening.** Limits are per IP only (30 per minute, process-local): no per-account lockout, and a flood from 4,096 distinct addresses blocks new logins. Password minimum is 8. Cookies are HttpOnly, Secure and SameSite Strict, which is good.
16. **Server hardening.** Root login by key only (fine), `X11Forwarding yes`, three pending package updates, and a non-root deploy user would be cleaner.
17. **Test gaps.** `internal/notifier` (webhook delivery), `internal/evaluator` and `internal/cache` have no tests; 68 page files have 26 test files (no tests for Home, Fleet, Guests, Revenue, Sites, Topology, Store, Security and others), and there are no end-to-end tests. One CI workflow only; Node 20 action deprecation warnings.
18. **Repository hygiene.** Six build files under `dist/` are tracked; legacy folders (`backend/` Python, `src/` prototype, `magichub/`, `ui-reference/`, `design-alternatives/`) add clutter. The AGENTS notes keep some on purpose.
19. **RouterOS command quoting.** `routerOSQuoted` escapes backslash, quote, dollar and control characters correctly. A sample of commands still interpolates values unquoted (interface names from configuration, sanitised guest names). Not exploitable as seen, but a test that forces every user-derived value through the helper would make it permanent.

## Checked and good
- **Tenant isolation:** transaction-local role and tenant ID with UUID validation, failing closed. A scan of all SQL found only two handler statements on a tenant table without a tenant filter, both in the platform-admin add-on decision (gated to the developer role).
- **Routes:** every tenant route sits behind origin check, authentication, active-tenant check, tenant context, minimum role and subscription gates. Public portal routes are rate-limited and body-limited. Admin-only actions are role-gated.
- **Authentication:** bcrypt cost 12, strict HS256 JWT validation with expiry, issuer and audience, a required non-default 32-character secret in production, HttpOnly Secure SameSite-Strict cookies, a CSRF header plus origin check.
- **Outbound requests:** webhooks go through an address guard at save time and at dial time; the Jellyfin client accepts only loopback and refuses redirects.
- **Database:** no table without a primary key; privileged functions pin their search path.
- **Server:** firewall with only SSH, HTTP(S), HTTP/3 and WireGuard open; key-only SSH; fail2ban and unattended upgrades active; environment file mode 600; clock synchronised; TLS certificate valid to 2027-01-16; containers healthy with no restarts and no warnings since the deploy; restart policies set.
- **Repository:** no secrets or key files committed; Actions pinned and least-privilege; `go vet` clean.
- **Frontend:** 1,433 translation keys identical in English and Burmese with none undefined; tokens in cookies, not browser storage; no stray console logging; main bundle 455 KB (127 KB compressed).
